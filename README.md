# pflege-simulator

German-language teaching simulator for nursing documentation (*Pflegedokumentation – Simulation*).
Ten student groups document daily vital signs and shift-aware care reports for ten fictional
patients. All identities and values are invented; the application refuses real patient data.

Status: foundation (Group 1 of
`openspec/changes/add-nursing-documentation-simulator/tasks.md`) is in place — scaffold, schema,
migration, seed, shared libraries, session/authorisation plumbing and the test harness. The
login, Vitalwerte, Pflegebericht and teacher surfaces follow.

## Stack

Next.js (App Router) + TypeScript (strict) + Tailwind CSS, Drizzle ORM on libSQL, Zod. Local
development uses a libSQL file; production uses Turso Cloud with `TURSO_DATABASE_URL` and
`TURSO_AUTH_TOKEN` on the server only.

## Local setup

```bash
npm install
cp .env.example .env.local      # then fill the two secrets
npm run hash-password -- --write  # writes SESSION_SECRET + TEACHER_PASSWORD_HASH to .env.local
npm run db:migrate               # creates .local/dev.db
npm run db:seed                  # 10 patients, 10 groups, access codes
npm run dev
```

`npm run db:seed` prints the ten group access codes once and writes them to
`.local/group-codes.txt` (gitignored, mode 0600). The teacher password generated by
`hash-password --write` is stored once in `.local/teacher-credentials.txt`.

## Commands

| Command | Purpose |
|---|---|
| `npm run dev` | Development server |
| `npm run build` | Production build |
| `npm run verify` | Typecheck, lint and unit/integration tests |
| `npm test` | Vitest (unit, integration, component) |
| `npm run test:e2e` | Playwright (browser suite, added with Group 8) |
| `npm run db:migrate` | Apply the tracked migrations |
| `npm run db:seed` | Idempotent seed; `-- --rotate "Gruppe 3"` regenerates one code |
| `npm run worktree -- create <branch>` | Parallel checkout with its own port and database |

Package manager is npm on this machine; `docs/parallel-work.md` records the frozen foundation
files and the group ownership for the remaining work.

## Notes

- Calendar dates are stored as `YYYY-MM-DD` strings, never timestamps; "today" is
  `Europe/Berlin`.
- One Vitalwerte record per patient and day is a database constraint, not a convention.
- Group access codes are hashed with scrypt; sessions are HttpOnly cookies whose tokens are
  stored only as a peppered SHA-256 hash.
